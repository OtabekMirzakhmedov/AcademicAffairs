# Deployment Guide - Render

This guide will help you deploy the AcademicAffairs application to Render.

## Prerequisites

- A Render account (free tier works fine)
- Your GitHub repository connected to Render
- This repository pushed to GitHub

## Deployment Steps

### 1. Connect to Render

1. Go to [Render Dashboard](https://dashboard.render.com/)
2. Click **"New +"** → **"Blueprint"**
3. Connect your GitHub repository
4. Select the `AcademicAffairs` repository

### 2. Render will auto-detect `render.yaml`

The `render.yaml` file in the root directory contains all the configuration needed:
- **Backend API** - Node.js web service
- **Frontend** - Static site
- **Database** - Persistent disk for SQLite

### 3. Configure Environment Variables

After the initial deployment, you need to manually set these environment variables:

#### Backend Service (`academic-affairs-backend`):

Go to your backend service → Environment tab:

```bash
# IMPORTANT: Update FRONTEND_URL after frontend is deployed
FRONTEND_URL=https://academic-affairs-frontend.onrender.com
```

**Note:** Other secrets (JWT_SECRET, JWT_REFRESH_SECRET) are auto-generated by Render.

#### Frontend Service (`academic-affairs-frontend`):

Go to your frontend service → Environment tab:

```bash
# IMPORTANT: Update this with your actual backend URL
VITE_API_URL=https://academic-affairs-backend.onrender.com
```

### 4. Redeploy After Setting URLs

After setting the environment variables:
1. Go to each service
2. Click **"Manual Deploy"** → **"Clear build cache & deploy"**

This ensures the frontend builds with the correct API URL.

## Database Persistence

The SQLite database is stored on a **persistent disk** mounted at:
```
/opt/render/project/src/backend/prisma
```

This means:
- ✅ Data survives deployments
- ✅ Migrations run automatically on each deploy
- ⚠️ Disk is 1GB (adjust in `render.yaml` if needed)

## First Time Setup

After deployment, the database will be empty. To seed it:

1. Go to your backend service in Render
2. Click **"Shell"** tab
3. Run:
```bash
cd backend
npx prisma db seed
```

This will create:
- Default roles (admin, departmenthead, teacher)
- Admin user (login: `admin`, password: `admin123`)
- Initial academic period

## Accessing Your Application

After deployment:
- **Frontend:** `https://academic-affairs-frontend.onrender.com`
- **Backend API:** `https://academic-affairs-backend.onrender.com/api`

Default login:
- **Username:** `admin`

## Important Notes

### Free Tier Limitations

- Services spin down after 15 minutes of inactivity
- Cold start takes ~30 seconds
- 750 hours/month free (enough for one service running 24/7)

### SQLite in Production

SQLite works well for:
- ✅ Small to medium user bases
- ✅ Development/testing environments
- ✅ Low concurrent write operations

For high-traffic production:
- Consider upgrading to PostgreSQL
- Render offers managed PostgreSQL

### Upgrading to PostgreSQL (Optional)

If you need better performance:

1. Create a PostgreSQL database in Render
2. Update `backend/prisma/schema.prisma`:
   ```prisma
   datasource db {
     provider = "postgresql"
     url      = env("DATABASE_URL")
   }
   ```
3. Update `DATABASE_URL` in backend environment variables
4. Redeploy

## Troubleshooting

### Backend won't start
- Check logs for Prisma migration errors
- Ensure DATABASE_URL is correct
- Verify all dependencies installed

### Frontend shows connection errors
- Check VITE_API_URL is set correctly
- Ensure CORS is configured in backend (already done)
- Verify backend service is running

### Database resets on deploy
- Ensure persistent disk is properly mounted
- Check disk is attached to the service
- Verify migrations are running (`prisma migrate deploy`)

## Manual Deployment Commands

If you prefer manual setup instead of Blueprint:

### Backend:
```bash
# Build Command
cd backend && npm install && npx prisma generate && npm run build

# Start Command
cd backend && npx prisma migrate deploy && npm run start:prod
```

### Frontend:
```bash
# Build Command
cd frontend && npm install && npm run build

# Publish Directory
frontend/dist
```

## Security Recommendations

For production use:

1. **Change JWT Secrets:**
   - Generate strong random secrets
   - Don't use auto-generated values in production

2. **Enable HTTPS:**
   - Render provides free SSL certificates
   - Already enabled by default

3. **Set Strong Admin Password:**
   - Change default admin password immediately
   - Enforce password policies

4. **Environment Variables:**
   - Never commit `.env` files
   - Use Render's environment variable UI
